# AGENT.md

Guidance for AI coding agents (and people) working in this repository.

## What this repository is

`noaa-apiroute` publishes Python clients for three NOAA APIs: api.weather.gov (the National Weather Service), the AviationWeather.gov Data API and the National Water Prediction Service API. The clients are **generated** by [apiroute](https://github.com/dougyouch/apiroute) from NOAA's published OpenAPI specs. Hand-written name maps in `specs/` give the operations their sections and method names. The clients are kept current by the weekly Build workflow, and released to PyPI as `noaa-apiroute`.

## Layout

| Path | What it is | Edit by hand? |
| --- | --- | --- |
| `apis.yaml` | The APIs: spec URL, docs URL, module, client class, auth base class, generator options | **yes**: this is the source of truth |
| `specs/<name>.json`, `specs/aviation.yaml` | The committed copies of the specs, written by `scripts/generate.py --fetch` | no (fetch them) |
| `specs/<name>.names.json` | Operation ID (or `"GET /path"` for the aviation spec, which has no IDs) → dotted name | **yes** |
| `specs/weather.pagination.yaml` | Which weather.gov operations get `_all` methods, and how they page | **yes** |
| `scripts/generate.py` | Fetches the specs, runs `apiroute generate`, writes the README table | yes |
| `scripts/next_release.py` | Each release's version, notes and CHANGELOG.md entry, from the commits since the last tag | yes |
| `src/noaa_apiroute/auth.py` | `NoaaAuth`: the User-Agent, weather.gov's optional API key, retrying read-only POSTs | **yes** |
| `src/noaa_apiroute/__init__.py` | Package docstring | yes |
| `src/noaa_apiroute/{weather,aviation,water}/` | The generated clients (every file starts with `# Generated by apiroute`) | **never** |
| `tests/` | Config checks and auth; `tests/live/` against NOAA's APIs | yes |
| `.github/workflows/` | `ci.yml`, `build.yml` (regenerate, live-test and commit), `release.yml` (every push to main: tag, PyPI, GitHub release) | yes |
| `.agent/skills/apiroute-client.md` | Skill for creating and maintaining repos like this one | yes |

## Rules

- **Never edit generated code.** CI regenerates from `specs/` and fails on any difference. To change generated output:
  - Edit `apis.yaml`, a name map, the pagination rules or `auth.py`, and regenerate.
  - If the generator itself is wrong, fix apiroute; the Build workflow picks up its next release.
- **Never patch a spec by hand.** The next fetch overwrites it. Work around spec errors with generator options in `apis.yaml` (`nullable_fields`, `open_enums`, `base_url`), or in apiroute.
- **Regenerate after any change** to `apis.yaml`, `specs/` or the scripts: `uv run python scripts/generate.py`. Add `--fetch` to download the latest specs first. Commit the specs and the generated code together.
- **Send a User-Agent that identifies the project** in anything that calls NOAA (live tests, scripts). api.weather.gov refuses requests without one.
- **Every merge to main is a release.** There's no release PR; `release.yml` tests, tags and publishes each push to main, Build's commits included.
- **Use conventional commits.** The version comes from the commits since the last tag:
  - `feat!:` (or a `BREAKING CHANGE:` footer) is a major release. Renaming a method in a name map is breaking.
  - `feat:` is a minor release
  - anything else (`fix:`, `docs:`, `chore:` ...) is a patch
- **The version lives in the git tag**, not `pyproject.toml` (hatch-vcs). Never tag by hand; the release workflow does.
- **Don't edit CHANGELOG.md by hand;** the release commits write it.
- **Before committing:** `uv run ruff check .`, `uv run ruff format --check .` and `uv run pytest`. After regenerating, also run the live tests: `NOAA_LIVE=1 uv run pytest tests/live`.

## Common tasks

- **NOAA added an operation:** generation still succeeds. The new operation lands on the root client, or in its tag's section, under a generated name. Give it a name in the API's `specs/<name>.names.json`, regenerate and commit (`feat:`).
- **Generation warns "--operation-names: no operation 'X'":** NOAA removed or renamed operation X. Remove or re-key its entry in the name map.
- **A spec change broke generation:** the Build workflow fails before committing anything. Reproduce with `scripts/generate.py --fetch --only <name>`, then fix apiroute or `apis.yaml`.
- **A live test fails after a spec update:** the spec and NOAA's responses disagree, or a typed model is wrong. Check the failing response. If the generator is at fault, fix apiroute. If the spec is, set `nullable_fields` (fields NOAA sends as null) or `open_enums` (enum values NOAA sends but the spec doesn't list) in `apis.yaml`. Type errors the options can't cover (a number declared a string) go in the README's notes for that API.
- **Release:** nothing to do. Every push to main, and every Build commit, is tested, released and published.
